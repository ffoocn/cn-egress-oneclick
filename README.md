# 一键安装与管理

纯 Bash 脚本。下载一个 `.sh` 文件即可运行，不需要 Python，也不会解压 Python 程序。

```bash
curl -fL https://raw.githubusercontent.com/ffoocn/cn-egress-oneclick/v2.3.1/cn-egress-oneclick.sh -o cn-egress-oneclick.sh && chmod +x cn-egress-oneclick.sh && ./cn-egress-oneclick.sh
```

支持 Debian 12+、Ubuntu 22.04+ 的 Linux 管理机和节点。按实际操作检测并安装缺少的依赖：打开菜单和离线查看配置不准备下载、编译或 VPN 工具。管理机需能连接所配置的 SSH 节点；国内出口是内网地址时，请在能访问该内网的机器上运行。

## 安装

选择 **1. 一键安装**，首次运行按提示填写三台节点。每个角色可以选择 **SSH** 或 **本机**；本机只能对应一个角色，大陆中转只填一台。

例如，在国内出口机上运行脚本时，将“国内出口”设为“本机”，香港与大陆中转设为 SSH。本机直接管理服务，不用再登录自己，不询问 SSH 用户、端口、私钥或密码；普通用户运行时通过 `sudo` 验证管理员权限。香港和大陆中转仍需填写客户端或出口机可以连接的公网 IPv4 地址，即使该角色使用本机管理。

SSH 节点按提示填写地址、用户和端口。密码隐藏输入，仅在本次进程中使用，不保存到节点配置。以前保存的节点配置继续按 SSH 方式加载。

填写节点时输入 `0` 可取消；取消或输入中断不会保存一半的节点或端口设置。

只有“一键安装”和“修改节点”进入节点配置向导。新管理目录选择“查看状态”“连接诊断”或“查看日志”会显示尚未配置及当前目录，不会要求填写三个节点；其他需要节点的操作会先提示配置，再准备所需依赖。以前使用另一个账号安装时，请使用原账号运行，或在同一账号下用 `CNE_HOME` 指向原管理目录。

选择本机表示直接在当前机器执行管理命令。香港入口仍需要手机能够连接的对外地址，大陆中转的地址用于其他节点连接及证书；如果网卡上能检测到公网 IPv4，会作为可修改的默认值。检测到私网或共享地址时，需手填云服务器公网地址或路由器映射地址。国内出口的本机地址可使用检测到的局域网地址。

修改已有节点地址或服务端口时，保存前会显示变更清单并保留旧节点设置。保存管理设置不会迁移或停止旧服务器上的服务，此后的菜单操作会使用新地址；需要选择“一键安装”部署新配置，并使用旧设置处理旧服务器。

- **三台都是新设备**：检查安装条件、补齐依赖，自动生成配置并安装。
- **发现旧配置，包括仅部分节点有旧配置**：显示具体节点，让你选择保留管理、备份后重新安装整套服务，或取消。
- **选择覆盖**：先备份全部节点的安装前状态，再安装。三台节点会使用新密钥，手机和 Windows 需要重新导入新客户端配置。
- **选择保留**：保留现有配置，直接使用管理菜单。缺少部署的节点在状态页显示“尚未安装”。

```text
一键安装与管理  v2.3.1
----------------------------------------

  1. 一键安装
  2. 修改节点
  3. 状态与服务
  4. 客户端管理
  5. 维护与设置
  0. 退出
```

主菜单只显示五个入口。“状态与服务”包含状态、诊断、启停、重启和日志；“客户端管理”包含设备列表、添加、配置与二维码、撤销；“维护与设置”包含备份、恢复、证书维护、下载来源、离线包和卸载。

交互终端切换页面时清除当前显示和滚动历史，操作结果保留到按回车，然后返回当前菜单。子菜单输入 `0` 返回上一级，主菜单输入 `0` 退出。重试或取消后仍留在当前层，无需反复寻找原功能；标准输入或标准输出经过管道或重定向时不清屏、不等待回车。仅将错误输出写入日志时仍显示交互提示并等待回车。命令行 `status`、`doctor` 等直接命令保持原行为。

上面的下载链接使用固定版本标签。`main` 链接末尾的 `?v=...` 只是缓存参数，不能指定下载某个历史版本。

状态页显示节点、服务状态和握手情况。状态、诊断和日志会分别查询每个节点；一个节点认证或连接失败时仍继续查看其他节点，并报告未完成的检查。启动、停止、重启和卸载仍要求先准备全部节点的登录信息。

节点设置损坏或不完整时，不加载一半的节点，也不退出整个菜单：可以离线查看已有设备文件，或通过“修改节点”重新填写。确认保存新设置后，原文件先保留在 `history/node-settings.*`；不安全的链接或文件归属会阻止覆盖。

## 客户端

新安装默认生成 AmneziaWG 2.0 配置，手机到入口的连接使用混淆参数。安装完成后生成 iPhone、Android、Windows 三份配置。进入 **客户端管理 → 显示配置与二维码** 查看文件位置或扫码，在支持 AmneziaWG 2.0 的原生客户端中导入并开启连接：

- **iPhone**：[App Store 的 AmneziaWG](https://apps.apple.com/app/amneziawg/id6478942365)，使用 2.0 或更新版本，建议更新到当前版本。
- **Android**：[AmneziaWG 官方客户端](https://github.com/amnezia-vpn/amneziawg-android/releases)，使用 2.0 或更新版本。
- **Windows**：[AmneziaWG 官方客户端](https://github.com/amnezia-vpn/amneziawg-windows-client/releases)，使用 2.0 或更新版本。

这类配置包含 `S3`、`S4` 和范围形式的 `H1–H4`，需要客户端支持相同的协议版本。应用和配置格式说明见 [Amnezia 官方文档](https://docs.amnezia.org/documentation/amnezia-wg/)。选择保留的旧 WireGuard 部署继续使用原 WireGuard 客户端；新增客户端也沿用该部署的入口协议和参数。保留旧部署不会自动为手机入口增加混淆。

二维码工具 `qrencode` 是可选依赖，不会阻止菜单启动或服务安装。显示二维码时才尝试补装；如果系统软件包状态异常、安装失败或二维码生成失败，会保留文件并直接显示完整配置内容，仍可导入 `.conf` 文件。显示的配置含私钥，请勿公开。脚本不会为此自动修复系统中的其他软件包。

默认文件目录为 `~/.local/share/cn-egress-shell/clients/`。新客户端可以随时通过 **客户端管理 → 添加客户端** 创建。保留旧部署时，已有客户端的私钥不会从服务器反向恢复，请继续使用原配置文件，或新增一个客户端。

每台设备使用独立配置。同类设备也需要通过“添加客户端”分别命名，不能共用一份 iPhone 或 Android 配置。

显示配置时先从列表选择设备，再选择核对服务器或离线查看。列表编号用于选择对应项；按名称选择时可输入 `n:设备名称`，避免数字设备名与编号混淆。核对模式会检查当前入口密钥、协议参数、完整地址、DNS、转发范围、预共享密钥摘要与设备注册信息，防止把换节点、重装、手改或撤销后的旧文件当作有效配置发放。离线模式不连接服务器、不安装依赖，明确标注尚未验证是否有效。撤销遇到回复丢失时会再次核对结果；重复撤销已不存在的设备可正确完成，本机旧文件标记为 `.revoked` 并保留历史版本。

## 运行与维护

再次运行同一个脚本即可打开菜单：

```bash
./cn-egress-oneclick.sh
```

也可直接查看状态或诊断：

```bash
./cn-egress-oneclick.sh status
./cn-egress-oneclick.sh doctor
```

默认管理目录是 `~/.local/share/cn-egress-shell/`，可用 `CNE_HOME` 指定绝对路径。节点地址存为 TSV 文本，配置不会作为 Shell 命令执行。旧版 Python 管理目录不自动转换；首次使用新版重新填写节点即可，服务器上的旧部署会被识别并给出处理选项。

选择 **维护与设置 → 备份配置** 会保存三个节点的配置、服务启停状态、管理设置及所有本机设备文件，并下载节点档案到管理机的 `backups/`。完整备份带文件校验；备份过程不停止服务，状态发生变化时不会把它标记为完整。服务器上的原始档案仍放在 `/root/cn-egress-backups/`，安装和维护记录放在管理机的 `history/`。这些文件包含私钥，请将完整备份目录另存到可信设备并保密。

选择 **维护与设置 → 恢复历史备份**，从列表选择完整备份。恢复要求原来的三个地址、角色和机器身份；可以调整 SSH 凭据或连接方式。恢复前会再备份当前节点，失败会逆序恢复。已卸载服务的原机器也可以恢复，服务器上的旧备份文件丢失时可使用已下载的档案。恢复会还原旧设备列表、密钥、端口和启停状态：后来新增的设备将失效，后来撤销的设备可能重新生效。原来停止的服务会继续停止，此时不会宣称链路已验证。它不用于把旧备份覆盖到不同机器。

选择 **维护与设置 → 证书续期与自动维护** 可手动更新传输证书。更新前自动保存完整备份，手机和电脑的设备密钥、配置文件保持不变；只重启原来运行的传输服务。三台更新完成并验证后才提交，失败会恢复原证书。

同一菜单可启用每天自动检查，仅在证书有效期不足 30 天时续期。管理机必须是运行 systemd 的 Linux，并保持运行。SSH 节点需要无需口令的 SSH 私钥登录，以及 root 或免密码 sudo；本机节点需要 root 或免密码 sudo。设置时会测试实际命令，并忽略临时 sudo 密码授权，避免第二天无法运行。自动维护不会保存、请求密码，也不会在后台安装缺失的软件包。菜单或其他维护占用管理锁时，会延后 15 分钟重试；关闭自动检查会取消尚未开始的重试，正在进行的维护会继续完成。状态和最近日志可以从菜单查看；更新脚本后可重新启用以更新定时任务所用的程序，卸载服务时会关闭本管理目录的自动检查。

启动或重启命令完成后，会继续检查全部节点的链路。服务命令成功但链路未通过时会显示失败原因与诊断、日志入口，不会把服务启动等同于可用连接。

安装前先保存全部节点的备份和 `prepared` 事务记录。安装或安装后的链路验证失败时，会逆序恢复本次已尝试安装的全部节点，包括先前已安装成功的节点，并恢复安装前的本地客户端配置。安装全部通过后才发布新客户端文件并提交记录。恢复遇到 SSH 断连等错误时，会明确显示未完成的节点并保留备份；下次安装会先重试恢复，再进行新安装。已补齐的系统依赖和单独确认启用的出口转发设置不会随配置回滚卸载或关闭。

安装、历史恢复或证书更新存在未完成的操作时，“维护与设置”子菜单才显示 **7. 重试恢复上次未完成操作**。恢复前可以查看状态、日志和诊断；修改节点、客户端及服务的操作暂时停止，避免破坏该次恢复所需的设置。

仅管理本工具的服务、网卡和防火墙规则，不更改宿主默认路由，也不卸载其他业务使用的软件。出口机未开启 IPv4 转发时，向导会先询问是否启用。已占用的业务端口或重叠的局域网网段会阻止安装，并说明冲突。

云安全组需放行客户端 UDP 端口（默认 51820）与中转 TLS 端口（默认 443）；已有网站占用 443 时可在节点设置中选择其他端口。脚本不会修改云平台安全组。

**连接诊断**会检查服务、节点握手和出口 DNS，并在香港节点使用保留的 `.250` 诊断客户端，从本机环回地址连接入口，验证经配置链路的 DNS UDP/TCP 查询和 HTTPS 访问。安装结束也会执行这些检查；验证失败时触发本次安装回滚。诊断客户端不显示在普通客户端列表中。

环回测试无法验证公网到香港的 UDP 可达性。安装完成后仍需在手机或 Windows 导入配置、检查实际连接，再使用税务应用完成真实登录和操作。混淆不能保证连接永远不被识别或封锁，也不能保证特定税务服务一定接受该出口。

## 源码与构建

`cn-egress-oneclick.sh` 是可独立运行的发布文件。项目自身的源码按职责放在 `shell/`，构建时以文本合并进一个 Shell 文件，不需要额外下载本项目的运行程序或使用 Python。第三方组件按下文所列固定版本获取。

```bash
bash build.sh
bash tests/run.sh
```

Shell 回归测试使用隔离文件和模拟节点操作；证书签发与校验使用真实 OpenSSL，覆盖配置生成、依赖安装计划、本机/SSH 管理、客户端管理、历史恢复、证书维护、无交互传输及缓存校验。固定 AmneziaWG 源码已使用 Go 1.24.4 实际交叉编译为 Linux amd64 和 arm64 程序。

另有可重复的 Docker Linux 测试 `tests/linux_smoke.sh`（环境见 `tests/Linux.Dockerfile`）。测试使用独立客户端、三个节点和受控 DNS/HTTPS 站点，验证生成的 AmneziaWG 手机配置、WSS 双向证书认证、DNS UDP/TCP、HTTPS、实际 systemd 服务与入口进程崩溃后的清理和恢复、宿主默认路由与转发状态保持、业务监听保留、中转中断后的阻断及探测清理。另有 `tests/linux_maintenance.sh` 验证实际 Linux 节点的证书更新、服务状态和历史恢复，`tests/download_linux_smoke.sh` 验证缓存导入后在禁用网络的全新容器里编译，以及损坏模块的拒绝。它们验证程序和网络逻辑，不代表已经在用户的手机、澳大利亚网络或现有服务器上实测。

运行时通过 HTTPS 下载固定版本组件，并验证 SHA-256；默认来源为官方，可显式配置镜像。AmneziaWG 使用用户态实现：管理机在私有工作目录下载 Go 1.24.4 和固定源码，编译对应节点架构的程序；香港节点在安装暂存目录使用 `gcc`、`make` 和 C 头文件编译控制工具。所有构建在替换服务前完成，不安装 AmneziaWG 内核模块或 DKMS，也不需要 Python。节点间传输继续使用固定版本的官方 wstunnel 二进制。第三方组件、固定版本和许可证说明见 [THIRD_PARTY_NOTICES.md](THIRD_PARTY_NOTICES.md)。

组件下载失败时会指出具体来源。选择 **维护与设置 → 配置下载来源** 可以设置 HTTPS GitHub/codeload 镜像前缀、Go 工具链下载目录及 Go 模块代理。主脚本使用的下载镜像不会自动传给组件；镜像设置不改变固定校验值。也可以使用 `HTTPS_PROXY`。Go 编译及依赖下载最多等待 10 分钟。

选择 **维护与设置 → 组件离线包**，在能联网的 Linux 管理机先“准备完整缓存”：下载 amd64/arm64 的固定工具链、传输组件及源码，实际完成两个架构的编译后保存所需 Go 模块。然后导出缓存包，在另一管理机导入。导入会验证归档内容、固定组件 SHA-256 和模块名单；不会导入别人编译的入口程序。安装仍从固定源码编译，Go 根据源码的 `go.sum` 重新校验模块。缓存不完整时会明确提示仍可能需要联网。

组件包不包含 Debian/Ubuntu 的系统软件包。管理机和三个节点仍需要预先安装所需系统依赖，或能访问 APT 软件源；导入组件包不能修复损坏的 dpkg 状态。
